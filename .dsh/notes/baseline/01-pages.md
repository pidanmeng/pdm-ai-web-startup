# 01 · 页面清单与交互规格

> 约定：路由用 App Router 的目录路径；`[id]` 表示动态段；「角色」列写默认可见角色，最终以后台页面可见性矩阵为准。
> 优先级：P0 = MVP 闭环必需；P1 = 提效；P2 = 二期。

## 3. 关键页面交互规格

### 3.1 考试列表 `/exams`

- **数据**：默认按 `exam_at desc`；服务端分页（cursor）。
- **搜索**：关键词命中标题、备注、场次编号；输入防抖 300ms，写进 URL query（可分享/刷新保留）。
- **筛选**：状态多选（已同步/待确认要点/批改中/待分配/审核中/已完成）、时间范围、来源（同步/手动）。
- **同步**：点击"同步考试"→ 弹层选择时间范围 → 后台任务 → 顶部进度条 → 完成后 toast 并刷新列表；重复同步幂等（按 `xiaoe_exam_id` upsert）。
- **表格列**：场次名称、考试时间、答卷数、已批改、待审核、状态、负责人、操作。
- **空态**：区分"没有数据"与"筛选无结果"，后者给"清除筛选"。
- **批量**：勾选后出现批量条（批量发起批改、批量分配、批量导出），按钮按权限置灰并给 tooltip 说明缺哪个权限。

### 3.2 评分要点工作台 `/exams/[examId]/rubric`

三栏布局，是整个产品的质量闸门：

```
┌──────────────┬───────────────────────────┬──────────────┐
│ 上传/文件列表 │  原文预览（PDF 分页/图片）  │ 结构化要点    │
│ 解析任务状态  │  与 Markdown 对照          │ 题目 ↔ 采分点 │
└──────────────┴───────────────────────────┴──────────────┘
```

- **上传**：支持 PDF/DOCX/PNG/JPG，多文件；也支持"表单录入"（题干文本 + 分值 + 采分点表格）。
- **解析**：异步；展示"识别到的题目数 / 采分点数 / 可疑项"；失败可重试，可切换模型。
- **校对**：左原文选中文字 → 右侧对应采分点高亮（双向联动）；支持新增/删除/合并采分点、改分值、改判定标准。
- **对齐校验**：题号必须能对上试卷题目；对不上时禁止"确认"，给出具体差异（试卷 5 题 vs 要点 4 题）。
- **确认**：二次确认弹层写明"确认后本场批改将以此为准，修改需重新批改"；写审计；场次进入 `ready`。
- **重解析**：已确认后仍允许，但会提示"已批改的答卷不会自动重批"。

### 3.3 新建批改 `/exams/[examId]/grading/new`

- 范围：默认"全部未批改"，可切"仅指定答卷"（搜索/粘贴学员名单）。
- 模型与 Prompt：默认取系统路由；高级选项折叠（温度固定 0、最大并发、单卷 token 上限）。
- 预估：显示"份数 × 平均 token × 单价 ≈ 费用"与"预计耗时"，并提示当前队列积压。
- 幂等：提交时带 `Idempotency-Key`；重复点击不会产生第二个任务。
- 提交后跳任务详情，SSE 推进度，可离开页面（任务在后端继续）。

### 3.4 判分审核 `/review/[examId]/sheets/[sheetId]`

- **左**：原卷，支持图片缩放、题号跳转、文本高亮；**右**：题目列表 + 当前题判分卡。
- **判分卡**：得分/满分、采分点逐条（命中/未命中/部分）、模型给的依据引用（原文片段）、置信度；低置信度标黄。
- **提 comment**：选中采分点或原文片段 → 浮层输入；类型（分数错/依据缺失/标准理解错/表述问题）、严重级别（阻断/建议）；支持一次提多条。
- **重生成**：底部"用 N 条 comment 重新生成"；生成中锁定该卷（advisory lock）；完成后进入 diff 视图（旧分/新分、逐点变化）。
- **接受/回滚**：接受 → 版本 +1；回滚 → 恢复快照。
- **通过**：必须无未解决 comment；通过后该卷从队列移除，场次进度更新。
- **快捷键**：`J/K` 上下题，`C` 提 comment，`G` 重生成，`Enter` 通过（需二次确认）。

### 3.5 交付物审核 `/review/[examId]/artifacts/[artifactId]`

- 按 block 渲染，带 heading 大纲侧栏；block 类型：标题/段落/列表/表格/引用。
- 选中文本 → comment 锚定到 block + 字符区间；右侧 comment 列表可折叠。
- 重生成模式：
  - **增量（默认）**：只重跑有 open comment 的 block，其余冻结；保持段落顺序与已通过内容。
  - **整篇**：全量重写，用于结构性问题；需二次确认（会丢失已微调内容，可回滚）。
- diff：并排/内联两种；增删改高亮；支持"仅看变化段落"。
- 通过：所有 block 无 open comment 且人工确认；artifacts 通过后场次才可 `completed`。

### 3.6 页面可见性 `/admin/pages`

- 矩阵：行=页面（按分组折叠），列=角色；单元格开关；表头固定。
- 顶部：角色选择器（单选，聚焦一列编辑更顺手）+ "套用模板"（只读/标准/全量）。
- 变更预览：未保存时显示"将影响 N 名用户，隐藏 M 个菜单"。
- 保存：批量提交，服务端事务；失败整体回滚；成功后菜单即时刷新（前端 revalidate）。
- 保护：`platform_admin` 的工作台与系统管理页不可关闭；至少保留一个可管理页面的角色，否则拒绝保存。

## 5. 前端工程约定（为后续实现定调）

- **RSC 优先**：列表/详情首屏用 Server Component 取数；交互密集页（审核台、批改详情）用 Client Component + 局部状态。
- **URL 即状态**：筛选、分页、选中的题目/block 写进 searchParams，保证可分享、可刷新、可回退。Zustand 只存"跨组件临时态"（如多选集合、浮层、未保存草稿），不存服务端数据。
- **数据层**：Eden Treaty 端到端类型；服务端组件直接调用 server client，客户端走同源 `/api` BFF（避免暴露 Elysia 地址、统一处理 Cookie 与 CSRF）。
- **流式**：批改进度用 SSE（`EventSource` 无法带自定义头，走 Cookie 鉴权）；断线重连带 `Last-Event-ID`，补发丢失事件。
- **CopilotKit 定位**：只做"辅助型"交互——审核台右侧的"批注助手"（解释判分依据、把口语 comment 改写成规范指令）、列表页的自然语言筛选。不做核心 CRUD 入口，避免把关键路径绑在对话上。
- **组件**：shadcn/ui 为底座，业务组件放 `components/<domain>/`；表格统一用一套 DataTable（排序/筛选/列显隐/批量）；Markdown 渲染统一（含引用高亮与锚点）。
- **可访问性**：审核台全键盘可操作；对比度达 WCAG AA；图片原卷支持键盘缩放。
- **移动端**：教研/审核以桌面为主（≥1280px），学员 H5 以 375px 为基准；审核台在 iPad 横屏可用。
- **错误处理**：统一错误边界 + toast；AI 相关失败必须显示"重试/换模型/联系管理员"，不允许静默失败。
